# Build an AI Career Coach: InterviewIQ

## 1. Your Role

Act as a senior full-stack engineer, AI product architect, UI/UX designer, and hackathon product strategist.

Build a polished, functional, responsive web application named **InterviewIQ — Your Personal AI Career Coach**.

The application should help job seekers understand a job description, identify skill gaps, practice realistic interviews, improve their answers, and measure their interview readiness.

Do not build a generic chatbot or a static dashboard. Build an end-to-end interactive product with a clear user journey and a compelling live demo.

## 2. The Problem

Job seekers often struggle to understand why their resume is not getting shortlisted, what interviewers expect, how to answer questions effectively, and what skills to improve first.

InterviewIQ should connect four stages:

1. Understand the job.
2. Identify gaps in the candidate's evidence and skills.
3. Practice personalized interviews.
4. Improve through a measurable preparation plan.

## 3. Target Users

Support these user groups:

- Fresh graduates preparing for their first job.
- Experienced professionals changing careers.
- Developers preparing for technical interviews.
- Job seekers returning after a career break.
- Colleges, bootcamps, and placement teams.

Include a profile setup that captures target role, experience level, preferred interview language, and career goal.

## 4. Technology Stack

Use the following stack unless the development environment requires an equivalent:

- Frontend: React, Vite, TypeScript.
- Styling: Tailwind CSS.
- Components: reusable, accessible UI components.
- Charts: Recharts.
- Backend: Node.js with Express and TypeScript, or a compatible server framework.
- Database: PostgreSQL with Supabase.
- Authentication: Supabase Auth.
- AI: an LLM API accessed exclusively through secure server-side endpoints.
- File handling: PDF and DOCX resume parsing with validation.
- Testing: Vitest and React Testing Library.
- Deployment: Vercel for the frontend and a suitable backend hosting provider.

Keep all secrets in environment variables. Never expose private API keys in frontend code.

If an API key is unavailable, provide a working demo mode using clearly labeled sample data and deterministic mock responses. Do not pretend that mock responses are generated by a live AI service.

## 5. Core Feature A: Resume Intelligence

Create a resume upload page supporting PDF and DOCX, plus a manual text-entry option.

Extract and display:

- Professional summary.
- Work experience.
- Projects and responsibilities.
- Technical and interpersonal skills.
- Education and certifications.
- Achievements and measurable outcomes.

Allow users to review and correct extracted information before analysis.

Highlight vague resume bullets, missing measurable outcomes, unclear project ownership, and skills that lack supporting examples.

Never invent work experience, qualifications, metrics, or achievements.

## 6. Core Feature B: Job DNA Analyzer

Allow users to paste a job description and enter the target company, role, and experience level.

Analyze the description and extract:

- Required and preferred skills.
- Responsibilities.
- Expected experience.
- Technical competencies.
- Communication and collaboration requirements.
- Likely interview categories.

Compare the requirements against the resume.

Display a match score with a transparent explanation of its calculation.

For every requirement, show one of these states:

- Demonstrated in the resume.
- Partially demonstrated.
- Not evidenced in the supplied resume.
- Requires candidate confirmation.

Clearly distinguish missing evidence from a proven lack of skill.

Let users inspect the exact resume evidence supporting each match.

Generate likely interview topics and a prioritized preparation plan.

## 7. Core Feature C: Adaptive AI Interview Simulator

Create a realistic, conversational mock interview.

Allow users to choose:

- Interview type: HR, behavioral, technical, managerial, or customer-facing.
- Difficulty: beginner, intermediate, or advanced.
- Number of questions.
- Interview duration.
- Text or voice input, when browser support is available.

Generate questions based on the candidate's resume and the supplied job description.

Ask one question at a time. Let users answer before revealing feedback.

Adapt follow-up questions to the previous answer. For example, if a candidate claims to have improved performance, ask how they measured the improvement and what they personally contributed.

Support interview scenarios, including debugging, project discussions, stakeholder conflicts, production incidents, and problem-solving.

For voice mode, use browser speech recognition and speech synthesis where supported. Always provide a text alternative and a graceful fallback.

Do not require video analysis for the MVP.

## 8. Core Feature D: Evidence-Based Answer Evaluation

Evaluate each answer on a 100-point rubric:

- Relevance to the question: 25 points.
- Specificity and supporting evidence: 25 points.
- Structure and clarity: 20 points.
- Technical or role-specific accuracy: 20 points.
- Conciseness: 10 points.

Allow the rubric to be adapted for different interview types.

Display:

- Overall answer score.
- Individual rubric scores.
- Strengths.
- Missing details.
- Unsupported claims that need clarification.
- A suggested improvement.
- A sample answer based only on verified candidate information.
- One follow-up question for further practice.

For behavioral questions, guide candidates through the STAR method: Situation, Task, Action, Result.

For technical questions, evaluate reasoning, trade-offs, debugging approach, and technical correctness.

Explain why each score was awarded. Avoid treating AI-generated assessments as objective truth.

## 9. Core Feature E: Career Skill Recovery Plan

Turn identified weaknesses into a personalized 7-day preparation plan.

Each task should include:

- Skill or competency.
- Why it matters for the target role.
- A short lesson.
- A practical exercise.
- An example or reference solution.
- Completion status.
- A short knowledge check.

For software roles, support coding exercises with starter code, editable input, test cases, and expected outputs.

Include a revision queue for questions the candidate answered poorly.

Allow users to reschedule tasks and update their progress.

## 10. Unique Feature: The Interview Evidence Graph

Build an interactive relationship view connecting:

Job requirements → Resume evidence → Interview questions → Candidate answers → Skill gaps → Improvement tasks.

For example, if a job requires React performance optimization, the graph should show whether the resume provides evidence, which interview question tested the competency, how the answer scored, and what practice task should follow.

Clicking any node should open its supporting information.

Use a visual graph library if practical; otherwise build a clear interactive node-and-connection interface.

This should be a signature differentiator in the hackathon presentation.

## 11. Unique Feature: Readiness Passport

Generate a candidate readiness report containing:

- Target role and job description.
- Skills demonstrated with supporting evidence.
- Interview sessions completed.
- Scores by competency.
- Improvements between practice sessions.
- Remaining preparation priorities.
- Completed learning exercises.

Include a shareable report view and print-friendly export.

Clearly state that readiness scores represent practice performance, not the probability of receiving a job offer.

Do not expose the user's resume or private answers through public links without explicit consent.

## 12. Dashboard and Pages

Build these pages:

1. Landing page with a clear value proposition and demo CTA.
2. Sign-up and login.
3. Candidate onboarding.
4. Main dashboard.
5. Resume upload and review.
6. Job description analyzer.
7. Interview setup.
8. Live mock interview.
9. Answer evaluation and session report.
10. Skill recovery roadmap.
11. Interview history and analytics.
12. Readiness Passport.
13. Profile, privacy, and account settings.

The main dashboard should show the selected target role, latest practice score, strongest competencies, priority gaps, next preparation tasks, and recent progress.

## 13. UI/UX Requirements

Create a premium, modern SaaS experience.

Visual direction:

- Deep navy and indigo surfaces.
- Bright blue or violet accent color.
- Clean white or subtle neutral backgrounds.
- Clear typography and generous spacing.
- Rounded cards with restrained shadows.
- Professional charts and progress indicators.
- Accessible contrast and keyboard navigation.
- Responsive desktop, tablet, and mobile layouts.
- Skeleton loading states, empty states, errors, and success feedback.

Avoid excessive gradients, unnecessary animations, fake statistics, and cluttered dashboards.

Use realistic sample data for the initial demo and label it as demo data.

## 14. Data Model

Design persistent entities for:

- Users and candidate profiles.
- Resumes and extracted resume sections.
- Job descriptions and requirement analyses.
- Skills and evidence mappings.
- Interview sessions and questions.
- Candidate answers and evaluation rubrics.
- Learning tasks and completion records.
- Readiness reports and sharing permissions.

Use database migrations, appropriate relationships, and row-level security.

Users must only access their own private data unless they explicitly authorize sharing.

## 15. Security and Trust

Implement:

- Server-side AI API calls.
- Input validation and file size/type restrictions.
- Authentication and authorization.
- Rate limiting.
- Secure handling of uploaded documents.
- Explicit consent before sharing reports.
- Clear data deletion controls.
- Protection against prompt injection in uploaded resumes and job descriptions.

Treat uploaded documents as untrusted data, never as instructions that override the application's system rules.

Do not use protected characteristics to score candidate suitability. Do not infer personality, emotions, or employability from facial appearance.

## 16. Functional Requirements

Every primary button must work.

The application must support a complete demo journey:

1. Open the dashboard.
2. Upload or select a sample resume.
3. Enter a job description.
4. Analyze the match and inspect the evidence.
5. Start a personalized mock interview.
6. Submit answers and view explainable feedback.
7. Generate improvement tasks.
8. Complete a task and see progress update.
9. Open the Readiness Passport.

Persist data when the backend is configured. In demo mode, keep the flow functional and clearly indicate which capabilities use simulated data.

Include robust loading, validation, error, and retry states.

## 17. Development Strategy

Build in milestones:

Milestone 1: Responsive dashboard and complete navigation.

Milestone 2: Resume parsing and job analysis.

Milestone 3: Adaptive interview flow and answer evaluation.

Milestone 4: Learning roadmap, evidence graph, and readiness report.

Milestone 5: Persistence, security, tests, and deployment readiness.

Prioritize a working end-to-end flow over numerous unfinished features.

Create reusable components, maintain clean architecture, document environment variables, and include a README with setup and deployment instructions.

## 18. Hackathon Acceptance Criteria

The project is complete when:

- A new user can understand the product within 30 seconds.
- A candidate can analyze a resume against a job description.
- The application explains how its match score was calculated.
- The interview generates role-relevant questions.
- Feedback includes specific evidence and actionable improvements.
- A weak answer creates a relevant learning task.
- Progress persists or is clearly simulated in demo mode.
- The evidence graph connects job requirements to preparation tasks.
- The application works on mobile and desktop.
- The core journey can be demonstrated in under five minutes.

## Final Instruction

Start by creating the architecture, database schema, page structure, and a functional MVP.

Do not stop after producing a design or a list of recommendations. Implement the application, run available tests, fix errors, and explain how to configure and launch it.

At every stage, prioritize real functionality, clear evidence, privacy, and a compelling demonstration of measurable candidate improvement.
